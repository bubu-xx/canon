# work：Canon を根拠にした修正・追加開発

課題：$ARGUMENTS

## 手順
1. **材料を集める**：MCP の `context_pack`（または `canon context --text "<課題文>"`、要素 ID が分かれば `canon context <ID>`）で、対象要素・関連要素・止まるべき条件・未回答の質問・実装とのズレを得る
2. **止まるべきか判断する**：`stop_conditions` に、この課題で触る項目が含まれていたら**着手しない**。該当する質問を利用者に示し、回答を待つ（ask スキル）
3. **課題の種類を見分ける**：
   - Canon どおりに実装されていない（バグ）→ Canon を正としてコードを直す
   - 仕様そのものを変える（追加開発・仕様変更）→ 先に Canon を変える。新しい値の根拠は利用者の回答（質問を起票して回答を得る）か、新しい版の情報源。根拠の無い仕様変更をしない
4. **影響範囲を出す**：変える要素について MCP の `impact`（または `canon impact <ID>`）で見直しが要る要素を確認する
5. **実装する**：コードと試験を直す。対応する要素 ID をコードのコメントか試験名に入れると、以後の観測で対応付けが確実になる
6. **検算する**：試験を実行 → observe スキルで観測 → `canon drift` でズレが無いこと、`canon validate` でエラーが無いことを確かめる
7. **報告する**：変更内容、根拠にした Canon の要素と出典、影響範囲、残った未確定事項
