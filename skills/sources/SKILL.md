# sources：情報源のテキスト化

情報源は Canon の根拠そのもの。**原文を変えずに**、引用できる単位ごとに位置を付けてテキスト化する。

## 規則
- 出力先：`.canon/sources/<文書名>_<版>.md`（1文書1ファイル）
- 引用できる最小単位（節・項、Excel のセル範囲、表、箇条書きのまとまり）ごとに、直前に1行のアンカーを置く：
  ```
  <!-- src: 文書名 版 位置 -->
  ```
  例：`<!-- src: 詳細設計書 v2.0 シート7 B10:F14 -->`、`<!-- src: 要件定義書 v1.3 §4.2.1 -->`
- アンカーの表記が、そのまま Canon の `source.ref` になる。文書名・版・位置を必ず含める
- 本文は**原文どおり**。要約・言い換え・補完・誤字の修正をしない。表は Markdown の表に、図は「（図：〇〇。内容はテキスト化していない）」と書いて飛ばす
- ファイル先頭に `<!-- 元ファイル: ... をテキスト化 -->` を書く
- 版が上がった文書は、古いファイルを書き換えず、新しい版のファイルを別に作る（既存ファイルの書き換えはフックで止められる）

## Markdown・テキストの文書
Markdown とテキストは、AI が書き写さずに `canon sources import <ファイルかフォルダー>...` で取り込む（原文の行を変えず、見出し・段落・項・表・コード例ごとに機械的にアンカーを付ける。同じ文書・同じ版からは必ず同じアンカーになる）。
- 文書名はプロジェクトのルートからの相対パス（`/` は `-`、拡張子なし）、版は git の最終コミット日（`--version` で指定もできる）
- フォルダーを渡すと、その下の Markdown をすべて取り込む（.git・target・node_modules・vendor・dist は飛ばす）。テキストファイルは名前を指定したときだけ
- 何を情報源にするか（README、docs、設計メモ、変更履歴など）は利用者と決める。外部から取り込んだライブラリの文書（vendor など）は、そのプロジェクトの設計ではないので入れない
- 取り込んだ後に原文を書き換える必要は無い（本文はそのまま）。人の確認は「何を情報源にしたか」の一覧で足りる

## Word・Excel・PDF の文書の手順
1. 元ファイルを読む（Excel は openpyxl、Word は python-docx、PDF は pdftotext などを使ってよい）
2. 上の規則でテキスト化して書き出す
3. 利用者に、作ったファイルと「原文どおりか差分で確認してほしい」ことを伝える（情報源の正しさは人が保証する）
